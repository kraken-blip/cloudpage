# CloudPage

Локальный форк [Homepage](https://github.com/gethomepage/homepage), исходная ревизия `65ebc6abd321233bfa0aed382565221c359759bb`, лицензия GPL-3.0 в LICENSE. Личный интерфейс из макета, API карточек и упаковка созданы с помощью ИИ. В отдельной Next.js-сборке используются проверка пароля Homepage, NextAuth и защита по Host. Приложение открывает панели обычными ссылками в новой вкладке. Карточки добавляются после входа. Начальный список пуст.

## Установка

На чистой Ubuntu 22.04, 24.04, 26.04 или 26.10 (amd64/arm64) установщик самостоятельно подключает подписанный [официальный репозиторий Docker](https://docs.docker.com/engine/install/ubuntu/) и устанавливает Docker Engine, Compose, Buildx и необходимые системные пакеты. Если Docker уже установлен, установщик использует его без обновления и перезапуска. Конфликтующие пакеты и следы старой установки останавливают автоматическую установку до изменения APT. Для других Linux нужен готовый локальный Docker Engine 28+, Compose с поддержкой `up --wait`, Buildx, Python 3 и обычное сопоставление UID. Во время сборки Docker получает Node и зависимости из публичных реестров. На VPS откройте оболочку root (`sudo -i`) и выполните:

```bash
( set -eu; test "$(id -u)" = 0 || { echo 'Откройте терминал от root (sudo -i).'; exit 1; }; umask 077; tmp=$(mktemp /root/.cloudpage-install.XXXXXX); trap 'rm -f -- "$tmp"' EXIT; curl -fsSL --proto '=https' --proto-redir '=https' https://raw.githubusercontent.com/pos87-blip/cloudpage-public/main/exports/cloudpage-install.run -o "$tmp"; grep -qxF CLOUDPAGE_PACKAGE_EOF "$tmp"; bash -n "$tmp"; mv -fT -- "$tmp" /root/cloudpage-install.run; bash /root/cloudpage-install.run )
```

Команда скачивает установщик из ветки `main` и сохраняет его в `/root/cloudpage-install.run`. Эту копию можно повторно открыть командой `bash /root/cloudpage-install.run`.

В стартовом меню выберите пункт 1 для установки CloudPage с готовым Docker. Если Docker отсутствует, пункт 1 возвращает в меню. Выберите пункт 2 для установки Docker, затем пункт 1. Пункт 2 проверяет уже установленный Docker и может предложить отдельно добавить Buildx из текущих репозиториев APT. Пункт 3 открывает меню уже установленной панели. Пункт 4 обновляет инструменты управления без перезапуска контейнеров. Пункт 0 в меню управления возвращает в меню установщика, если оно открыто через установочный файл. Укажите свободный локальный порт, способ доступа и данные для входа.

1. **Отдельный публичный HTTPS.** Введите публичный IPv4 этого сервера или DNS-имя с A-записью на него. Для встроенного прокси нужны свободные входящие TCP 80 и выбранный HTTPS-порт (по умолчанию 443) и доступ к Let's Encrypt. Прокси публикует IPv4, поэтому для имени с AAAA выберите существующий прокси. Установщик поднимает Caddy как второй контейнер проекта, выдаёт сертификат Let's Encrypt для имени или короткоживущий сертификат для IP. Caddy хранит ключи и продлевает сертификат автоматически.
2. **Существующий HTTPS-прокси.** Введите полный адрес. Владелец прокси настраивает передачу запросов и исходного Host на `127.0.0.1:17840`. Установщик проверяет получившийся HTTPS с обычной проверкой сертификата и сопоставляет страницу входа с локальной сборкой.
3. **Приватный SSH-туннель.** Меню покажет команду SSH и адрес для открытия на своём компьютере. В этой схеме все порты приложения доступны только на loopback.

При установке укажите свободный локальный порт или нажмите Enter для 17840. В режиме встроенного Caddy установщик отдельно запрашивает публичный HTTPS-порт. По умолчанию 443. Чтобы задать локальный порт заранее, выполните, например, `sudo HOMEPAGE_PORT=17841 bash ./install.sh`. Установщик не меняет DNS, существующие прокси, VPN или правила сетевого экрана. Занятые 80 или выбранный HTTPS-порт останавливают установку встроенного прокси. Включите их доступность у провайдера заранее. Проверка HTTPS выполняется с самого VPS и требует, чтобы он мог открыть выбранный адрес. Если маршрутизация, DNS или выпуск сертификата задержались, выберите пункт 1 меню после устранения причины.

## Граница доступа

Каталог `/opt/cloudpage` принадлежит root и имеет режим 0700. Файл доступа `admin.json` имеет режим 0400 и подключён только для чтения. Пароль администратора находится в этом закрытом файле, ключ сессии генерируется на месте. Процесс работает с UID/GID 1000, пишет прикладные данные в собственный каталог `data` с режимом 0700. Корневая файловая система образа доступна только для чтения. У контейнера отдельные пространства имён и собственная bridge-сеть проекта, сброшены все capabilities, задан no-new-privileges. Docker API, чужие файлы, PID и сеть хоста контейнеру не передаются. Порт самого кабинета публикуется только на 127.0.0.1. В режиме встроенного HTTPS только отдельный Caddy слушает публичные TCP 80 и выбранный HTTPS-порт и использует собственные каталоги TLS. У bridge-сети есть штатный исходящий доступ, как у обычного контейнера Docker. Приложение не опрашивает серверы из карточек, браузер открывает их напрямую. Администраторы Linux и владельцы доступа к Docker Engine контролируют контейнеры и могут прочитать их данные. Доверяйте им как администраторам приложения.

Ссылки хранит `data/services.yaml`, редактируется группа «Мои серверы». Изменение синхронно проверяет ревизию файла в одном экземпляре процесса. Запускайте одну реплику. Предыдущее состояние сохраняется в `data/services.yaml.bak` с режимом 0600. Пароли панелей хранятся в менеджере паролей браузера. При переносе старой конфигурации остановите сервис, сделайте резервную копию и импортируйте только проверенные ссылки без учётных данных в URL. YAML при сохранении форматируется заново.

## Управление и откат

По окончании установки в терминале открывается меню. Повторный вход — `sudo cloudpage`. Меню проверяет адрес, показывает состояние, журнал и команду SSH для приватного режима. Запуск, остановка и перезапуск применяются к сервисам этого Compose-проекта, включая встроенный Caddy, если он установлен.

Для смены логина или пароля администратора выберите пункт 4 или выполните `sudo cloudpage --credentials`. Enter оставляет текущее значение. Терминал скрывает ввод пароля и запрашивает повтор. После подтверждения утилита обновляет закрытый файл доступа с правами 0400, меняет ключ сессий и пересоздаёт только сервис web. Caddy продолжает обслуживать HTTPS. Утилита проверяет новый вход через локальный интерфейс и пытается восстановить прежние данные, если проверка или пересоздание завершились ошибкой. На время пересоздания возможен короткий перерыв в доступе к кабинету.

Пункт 3 меняет локальный порт. При ошибке восстанавливается прежний порт. Для SSH-туннеля или отдельного внешнего прокси укажите новый порт как порт назначения. Публичный HTTPS-порт собственного Caddy сохраняется.

Пункт 10 удаляет CloudPage вместе с карточками, ключами TLS и Docker только если его установил текущий установщик, а сервер Docker не содержит сторонних ресурсов. Для удаления нужно ввести `УДАЛИТЬ`. На ранее установленных экземплярах без записи о происхождении Docker этот пункт не выполняется.

Откройте root-shell в `/opt/cloudpage` с локальным Docker context. Для диагностики и управления отдельной службой:

```bash
docker compose ps --all
docker compose logs --tail=80
docker compose stop
docker compose up -d --wait
docker compose restart
```

Перед переносом или обновлением сделайте закрытую копию, пока запись остановлена:

```bash
umask 077
docker compose stop
archive=$(mktemp /root/cloudpage-backup.XXXXXXXX.tar.gz)
tar -czf "$archive" .
tar -tzf "$archive" >/dev/null
docker compose up -d --wait
```

Для отката последнего редактирования остановите web, скопируйте `data/services.yaml.bak` в `data/services.yaml` с правами 0600 и владельцем 1000:1000 (`install -o 1000 -g 1000 -m 0600 data/services.yaml.bak data/services.yaml`), затем запустите web. Для отката первого запуска выполните `docker compose down` из каталога проекта. Команда снимает контейнеры проекта и его сеть, а закрытые данные остаются в каталоге. Для восстановления записей из архива остановите web и восстановите файлы в этот же каталог, сохраняя владельцев и права. При восстановлении старой полной копии обновите ключ secret в admin.json и пересоздайте web, чтобы отозвать прежние сессии.

Требование Docker Engine 28+ связано с защитой loopback-публикации от доступа из локального L2-сегмента. [Документация Docker](https://docs.docker.com/engine/network/port-publishing/).
